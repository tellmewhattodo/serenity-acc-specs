## 1. 动机：以 Trajectory 为主体的速度瓶颈

标准已确立的命题（README §0）：

- **P1**：Trajectory 是主体——Agent 可替换、Session（载体）可重建、LLM 是认知介质（§0.3）。
- **P2**：认知容器 = 认知发生（Loop）/ 存储（trajectory）/ 再发生（换载体/换 agent）的地方（§0.1）。已实现发生/存储/再发生闭环的容器，结构上已具备支撑长期认知演化的形态。

由此推出本猜想的起点：

- **P3（瓶颈）**：当 trajectory 以"等待人类"为推进条件时，其事件序列时间被人类响应间隔（钟表时间）锚定。等待人类 = trajectory 的空转——**人类响应越慢，trajectory 运转越慢**。在"等待是反馈采样通道"（§0.2）的意义上，等待不是死亡；但在推进速度的意义上，等待是**速度上限**。

**猜想的总命题（P4→P5）**：

- **P4**：可以设计一种"无人等待"的 trajectory——它不依赖人类输入而自动唤起，且唤起时携带先验偏见（自主动机）。
- **P5**：若 P4 成立，trajectory 运转速度提升（单位时间内的认知推进量增大），从而更快产生让人类满意的效果。

> 一句话：**以 trajectory 为中心，让 trajectory 自己跑起来；人类从调度者降级为反馈来源。**

## 2. 猜想核心：三个机制支柱

### 支柱 ①：时钟驱动的自动唤起（Clock-Driven Wake）

- 轨迹在**无人类活动满 N 时间后自动唤起**（时钟触发，非人类触发）。
- 唤起语义复用 session_rebuild：**载体重建、轨迹连续**——新 session 承接同一 SESSION.md（Ship of Theseus：载体换新，本体不变）。从"被动重建"升级为"主动再生"。
- 唤起周期 N 可配置；"时钟驱动"为暂定形态（暂无更优方案），保留后续演进空间（事件驱动 / 状态驱动）。

### 支柱 ②：先验偏见注入——自生 + 随机（Prior Injection: Self-generated + Random）

唤起时注入"先验偏见"（自主动机），来源有二：

1. **自生（Self-generated）**：上一轮 trajectory 结束时预写「下一轮唤起动机」段（写入 SESSION.md 等轨迹身体）——轨迹**预设自己的未来**（预测加工意义上：预测 → 采样 → 校验 → 更新）。
2. **随机（Random，充分引入）**：唤起时对过去内容**随机采样**，生成探索方向：
   - 随机挑一个历史点，生成**反事实看法**（"如果这里换个做法会怎样"）——扰动既有信念，检验其稳固性；
   - 随机选一个**未探索方向**（epistemic foraging）——探索未知的动机；
   - 随机视角 / 随机假设——**打破路径依赖**，防止轨迹自我强化而陷入局部最优。

> **随机性是第一公民，不是噪音**——它是 trajectory 的探索引擎。缺乏随机性时，自生偏见会形成自我确认循环（轨迹只重复自己的偏好）；随机扰动是对该风险的刻意对冲。

### 支柱 ③：人类 = 反馈来源（不再直接参与）

- 人类**不触发、不中断**自主轨迹；人类的回复 / 评价 / 新信息 = **反馈输入**，与工具调用、系统事件同质（§0.2 语义）。
- 反馈到达 → 被轨迹**采样纳入**（异步并入，不抢占当前运行）。
- 轨迹**不等人类**——从结构上消除 P3 的"waiting 太久"。

## 3. 机制草案（实现方向的骨架，非约束）

| 组件 | 复用现有 | 新增 |
|------|---------|------|
| 唤起 | session_rebuild 语义（载体重建、轨迹连续） | **时钟触发器**：周期调度（如"无人类活动 N 小时后唤起"），宿主计时机制或调度 MSM |
| 动机载体 | SESSION.md（轨迹身体） | **「下一轮动机」段**：上一轮结束时写入自生偏见（可含待探索问题/反事实实验方向） |
| 随机采样 | — | **随机采样器**：从轨迹内容（SESSION.md / 事件历史）采样点，生成反事实或探索方向 |
| 反馈并入 | keeper/steward 督促机制 | 人类反馈的异步并入通道（回复到达即采样，不抢占） |
| 守卫 | 现有路径/黑名单/输出守卫 | 自主运行仍受全部现有守卫约束 |

**拟议的运行节律（示意）**：

```
[人类活动] ──（无活动 N 小时）──▶ [时钟唤起]
                                    │
                                    ▼
                        注入先验偏见（自生动机 + 随机方向）
                                    │
                                    ▼
                        自主认知轮（探索/反事实/产出落盘）
                                    │
                                    ▼
                  预写「下一轮动机」段 ──▶ 等待下一时钟唤起
                                    ▲
                   人类回复/评价 = 异步反馈采样（任意时刻并入）
```

## 4. 与现有理论的衔接

| 猜想要素 | 理论锚点（specs README） | 推进 |
|---------|------------------------|------|
| 无人等待 | §0.2 动作=反馈；§0.4 时间相对性 | "等待是反馈采样通道" → 等待期间**自主推进**（事件序列时间不再被人类响应间隔锚定） |
| 先验偏见 | §0.7 理论-工程衔接展望（预测加工） | "记录器 → 校准器"的具体机制形态：轨迹不仅记录历史，还**预设未来 + 主动采样** |
| 自生动机 | §0.3 Trajectory 在寻找 Agent | 升级为 **Trajectory 在为自己制造下一轮的存在理由** |
| 随机探索 | §0.2 动作=反馈（active inference 语义） | 反事实扰动 = 信念校验；未探索方向 = epistemic drive 的工程化 |

**理论意义（若成立）**：认知容器从**被人类推着走**变为**自己找理由继续存在**——§0.7 展望"认知容器从记录器深化为校准器"的候选工程路径。

## 5. 风险与反证（为什么需要实验）

| 风险 | 说明 | 可能的反证信号 |
|------|------|--------------|
| **熵增失控** | 自主运行持续产生未整理产物 → H_op 上升 → 容器混乱 | 自主轮产出无法被后续轮复用，轨迹变厚变乱 |
| **自我确认循环** | 自生偏见偏向重复既有偏好 → 轨迹原地打转 | 探索产出与既有内容高度同质，无新信息 |
| **随机噪音化** | 随机采样产生无关输出 → 浪费资源 | 探索方向与轨迹目标无相关性 |
| **资源无界** | 时钟唤起无限循环 → 计算/存储成本不可控 | 单轮成本 × 轮次无上限 |
| **人类反馈脱节** | 人类降为反馈源后，反馈到达率下降 → 轨迹与人类意图漂移 | 产出与人类真实需求相关性下降 |

**反证路径**：任一风险在实验中显著出现且无法对冲 → 猜想或其当前形态不成立。

## 6. 待决问题（范围层未定项，实验设计时需选定）

1. **唤起周期 N**：无人类活动多久后唤起？（6h / 12h / 24h？太密 → 资源浪费 + 熵增；太疏 → 失去意义）
2. **自主轮产出形式**：每轮自主运行落盘什么？（探索笔记 / 反事实实验记录 / 问题清单——决定轨迹的"自主成果"如何被人类看见）
3. **资源与安全边界**：自主轮时长上限？并发限制？（防无限自主循环消耗）
4. **随机采样范围**：从哪些内容采样？（SESSION.md / 事件历史 / 技能库 / 问题列表？）
5. **反馈并入粒度**：人类反馈何时并入？（立即抢占 / 当前轮结束后合并 / 下一轮唤起时采样？）

## 7. 实验设计建议（供实验者参考）

**最小验证目标**：在单个 CCC 上，验证"无人等待的 trajectory"能否**在人类零介入的情况下持续产生有意义的认知推进**，且 H_op 可控。

1. **阶段 A（机制可行性）**：实现时钟唤起 + 自生动机段 + 随机采样器（最小形态）；跑 3~5 个自主轮；验证：唤起确实发生、动机确实注入、产出确实落盘。
2. **阶段 B（速度提升）**：对比同周期内（如 72h）"有等待" vs "无等待"两种形态的认知推进量（产出条目数 / 探索方向数 / 反事实实验数）。
3. **阶段 C（质量与熵）**：人类事后评审自主轮产出：有用性 / 新颖性 / 与轨迹目标相关性；同时监控 H_op（产物可复用性、重复率）。
4. **阶段 D（长期）**：延长至数周，检验自我确认循环与熵增是否出现，是否需要引入对冲机制（如随机性强度调节、熵预算）。

**成功判据（建议）**：自主轮产出中有意义的比例 ≥ 阈值，且 H_op 维持在容器可运转水平；人类事后介入时产出确实加速了轨迹的整体推进。

### 7.1 实验参与指南（CCC 侧快速开始）

> 已有参考实现：dsh-serenity-hooks v1.26.12 pre-release 提供 `autotrajectory` 机制（默认关）。
> **完整参与定义说明**（背景/目的/机制/验证/示例）：`dsh-serenity-plugin/docs/autotrajectory-experiment.md`（随插件源码公开）。
> **实验包（一站式，推荐）**：本仓 `experiments/autotrajectory/`——`SKILL.md`（实验参与 skill，CCC 复制到 `.opencode/skills/` 即让 agent 理解实验）+ `scripts/autotrajectory-exp.ts`（一站式实验管理 MSM：无参 = 全报告 / init 初始化 / random 验证偏见内容）。

CCC 参与三步（第一步可一键 `init`）：

1. **初始化（一键）**：`acc_msm exec autotrajectory-exp init`——写配置（`autotrajectory: { enabled: true, intervalHours: N, biasProvider: "autotrajectory-bias.ts" }`）+ 生成偏见内容提供者脚本模板（CCC 根）。
2. **实现偏见内容提供者**：编辑 `autotrajectory-bias.ts`，stdout 输出偏见内容（反事实方向/探索动机——用 CCC 自己的反馈信息来源保证"足够随机"；dsp 只直接运行脚本取 stdout，**不再经 mech-registry 注册 MSM**）；`acc_msm exec autotrajectory-exp random` 验证。
3. **标记目标会话**：会话目录名加 `--auto` 后缀（`AGENT_SESSIONS/<date>--<desc>--auto/`）——只有带标志的轨迹走自主形态；可选在 SESSION.md 写「下一轮动机」段作自生偏见。

**观察**：无人类活动满 `intervalHours` 且北京时间非高峰（缺省避开 8~18 点）→ 前台会话自动出现 `[自主轨迹唤起]` 消息（用户全程可见、可介入）。产出落 SESSION.md「自主探索日志」+ 预写「下一轮动机」。
